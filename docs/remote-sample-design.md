# Bounded remote sample in the existing worker

Candidate design, 2026-10-05. This is not a deployment or evidence about any real account. All fixtures are newly synthetic. The production checkout and remote business records remain untouched.

## Outcome and integration

After a successful existing worker cycle, one due hook starts a bounded diagnostic child without waiting for its API calls. The next sync cycle can proceed while that child runs. No second daemon, external automation, or business-data repair is introduced. `status` reads a redacted cache only; `check --live` uses the same sample collector. A sample is evidence about the stated messages and time window, never full-history completeness or client rendering equality.

Engineering defaults (not API guarantees): 15-minute cadence, 30-minute cache lifetime, 10-minute stability buffer, preceding 24-hour creation window. The endpoint's create-time window cannot discover edits to older messages. Cadence may be disabled or set from 15 to 30 minutes; TTL is twice cadence, at most one hour. Cache age, last attempt, scope, counts, inconclusive reasons and unsupported comparisons remain explicit.

## Sampling and conclusions

Use the already-discovered local enabled received-chat inventory: two recently discovered hot-ranked chats plus three chats rotated in stable identifier order. This deliberately avoids another remote directory scan and undocumented shortcut HTTP fanout. Undiscovered/disabled/muted/inaccessible chats, older windows, thread-container-only replies and client-only dynamic rendering are outside the claim. Persist only the numeric rotation; refresh candidates every run. The inventory can change, so fairness describes rotation through each observed inventory, not guaranteed global coverage.

For each selected chat request at most two native message-list pages of 20 items. Freeze the time window, sort and container for pagination; validate envelopes, IDs, chat, timestamps, page sizes and token progression. A truncated page sequence is reported as a bounded partial sample, not complete window coverage. Empty, errored, unbound and interrupted samples cannot become a positive signal.

Compare ID/source/type/container first. Coverage history, detail debt and candidate records are read in one read-only SQLite transaction; revocation/deletion cannot combine an old coverage proof with a new absence. A missing record whose scope has not successfully covered the message's creation time remains pending synchronization. A successful coverage interval must come from the project's sole coverage implementation, not a cursor maximum or arbitrary worker success. Retain a bounded, private hash-keyed observation (DB/account/message/target) for a suspect; confirmation requires the same remote observation and a later successful interval covering that same target after the first observation. Retired run evidence and missing detail closure remain unverified. Unrevisited suspects remain unresolved and do not silently disappear into a healthy result.

Compare versions only when timestamps and native source semantics are usable. Detect explicit native identity, message-type and retraction contradictions. Compare static text/post API body JSON with canonical object-key ordering, retaining array order. Exclude sender names, renderer output and full raw-record hashes. Dynamic cards, merged forwards, legacy source shapes and unavailable versions explicitly count as content unverified. A newer local version is a race/unverified result. A newer remote version or same-version native static-body difference is a candidate discrepancy, not a claim that the client presentation was lost.

## Account binding and concurrency

An authenticated `open_id` alone does not prove DB ownership. Local evidence must either be a matching persisted binding from an initially empty DB that completed sync, or explicit, single, nonconflicting sent-self history matching the current principal. Unknown/mixed/mismatched identity fails closed. The evidence source is reported; this is account association evidence, not proof that every historical record belongs to one account. The sampler does not adopt an old DB, change permissions, or broaden OAuth scopes. Re-read identity and DB file context before accepting a result. A changed account/file invalidates observations/cache.

Sync and diagnostic API reads cooperate through one local process lease. Worker sync runs first. Foreground sync retries a busy lease for at most five seconds; it cannot preempt a request already in flight. The probe only tries the lease per request, never waits for it, never sleeps with it held and releases it in `finally`. A request has a four-second timeout. Busy cancels the partial sample. The diagnostic lease is never held for the whole 60-second child. A kernel flock releases on the final close, including process death; unsafe lock files fail closed. The held descriptor is inherited by an in-flight API subprocess, so killing its Node parent cannot prematurely release the request lock. One absolute five-second sync deadline bounds all acquisition attempts and helpers. This does not coordinate external clients or unrelated programs.

## Budgets, persistence and failure

At most twelve direct API invocations: two identity reads and ten message pages. A one-second minimum unleased gap after each diagnostic request is an application budget, not a separate official API quota. The entire collection shares a 55-second deadline, including request waits, pages and remaining-time SQLite budgets; scheduled and one-shot children both have a 60-second kill deadline. No in-run remote retries. Honor returned rate-limit reset durations; carry cooldown to later attempts and prevent diagnostic calls during known sync cooldown. Private UID-wide immutable operation cooldown records propagate known resets across cooperating worker, foreground sync, manual probe and database paths; corrupt evidence fails closed. Do not invent an undocumented identity endpoint rate threshold.

One atomically replaced private scheduler state stores due time, attempt state, capped exponential failure backoff (15 minutes to six hours), rotation and at most 200 hash observations (seven days). Reserve the next attempt under flock before any API request so a crash/restart after reservation does not create immediate request storms. A separate POSIX flock state lease prevents concurrent worker/manual cache-writing checks. Such manual checks share rotation, prior observations and due/backoff; not-due is explicit incomplete without a fresh API call. No-cache one-shot checks do not confirm or clear prior scheduled observations. A failed/busy attempt never renews an earlier success. Cache/state parse, future-time, DB/account mismatch and schema-policy errors fail closed. Evidence readers open with O_NONBLOCK and O_NOFOLLOW, validate private same-user regular files with one link, read through the opened descriptor, and reject metadata/path changes. All sample counters are bounded and cross-checked before normalization; a malformed count cannot become a positive signal. Cache/state atomic renames fsync both file and parent directory. Persisted files use 0600 and no IDs, names, links, bodies, raw CLI output or errors in public cache/log events.

## Official API references

Verified 2026-10-05 against [message list](https://open.feishu.cn/document/server-docs/im-v1/message/list), [user info](https://open.feishu.cn/document/server-docs/authentication-management/login-state-management/get) and [frequency control](https://open.feishu.cn/document/server-docs/api-call-guide/frequency-control).

- Message list documents page size 1–50, second-resolution start/end, create-time sorting, and 1000/minute plus 50/second limits. Those are documented endpoint limits at verification time, not our polling defaults or an SLA. Thread containers require distinct requests and do not support the same time filter; the sample does not claim to enumerate all replies.
- The documented card content selector is `user_card_content`. Older code uses `raw_card_content`, which this public endpoint document does not establish. The probe uses the documented selector and never compares dynamic card body representations.
- User info requires the current user token and returns application-scoped `open_id` and `tenant_key`. Its frequency tier is Special; no numerical threshold is assumed. Authentication failures remain diagnostic unavailability.
- Limits are generally scoped by API/app/tenant, shared with sync. HTTP 429 (or legacy 400), code 99991400 and `x-ogw-ratelimit-reset` indicate throttling; reset is a number of seconds to wait, not epoch time. Missing headers use the conservative local failure backoff. CLI shortcuts can hide multiple HTTP requests, hence the direct endpoints above.

## Implementation/review notes

The API lease uses one never-unlinked private UID-wide regular file. A short Python helper applies nonblocking flock to a duplicate of Node's descriptor; the shared open-file description retains the lock after the helper exits. This removes PID inspection, process claims and stale-owner recovery. This behavior was tested on the local macOS host using synthetic files: helper exit retains ownership, final close releases, and process crash releases once inherited request descriptors close. See [Apple flock documentation](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html). The scheduler uses a separate kernel flock in the bounded child. A short-lived guardian enforces a monotonic 60-second deadline, notices worker death, and terminates the probe process group even when the worker's synchronous event loop is busy; it has no scheduling loop or durable state of its own. The worker owns only one in-flight job. Both normal worker exit and sync exceptions stop it. A finite `--once`/max-cycle run cancels an unfinished diagnostic during cleanup; it does not wait for sampling. A persistent worker is the intended periodic host. Parent-exit detection is polled every 50ms by the guardian; the independent monotonic deadline still bounds the whole process group. The account sidecar is `<canonical-db>.remote-account-binding.json`, stores only hashes/time, and is ignored by Git. File-cache context retains the existing local diagnostics fingerprint for compatibility; account/observation state uses the stronger activity fingerprint including file birth identity. Both are checked again after collection.

A native API mismatch is evidence about the source payload. Dynamic card contents and client rendering remain unverified even when `update_time` matches. Undocumented `only_thread_root_messages` is not used. Rate documentation can change; the one-second local gap and twelve-call cap deliberately do not claim an independent official allowance.


## Root-review regression acceptance

The candidate must pass each reported counterexample, in addition to the general suite:

1. Actual `writeLog` → event reader → service/public report accepts only the explicit versioned schedule-event contract. Unknown fields and invalid outcome/reason pairs fail closed; schedule start does not manufacture sync activity or statistics.
2. A synthetic WAL writer atomically revokes coverage and deletes a record between reads. A single reader snapshot sees either the old proof plus record or the new absence without proof, never false confirmed missing.
3. Numeric, object, array, boolean, null and blank native message/chat IDs cannot be equal, healthy or sampled.
4. Account-binding and v3-cache files with 0666 mode or multiple hardlinks are rejected without chmod. Future/noncanonical binding time, symlink, FIFO and mid-read replacement are rejected. Binding publication fsyncs both file and directory.
5. Hot/fair/eligible/truncated counts obey selection and pagination relations; every current finding is bounded by the sample, historical counts by the 200-observation state. Failed samples retain valid partial counters but cannot bypass these checks. Direct summary projection also validates before displaying evidence.
6. A real synthetic FIFO state path returns invalid in an isolated two-second-bound child; worker sync still proceeds. A blocked fake probe cannot delay the next sync. Guardian termination covers worker exit, exception, deadline and descendants.
7. Repeated synthetic 1900ms lease attempts share one absolute five-second budget and the last attempt receives only the remaining time. These clock-injected deadline regressions are distinct from actual local OS flock ownership tests. Ordinary sync has no `ps` dependency.

No real account/API, production LaunchAgent, or deployed lifecycle validation is claimed. Those remain the independent production integration gate.


## Second root-review correction

Both manual execution paths (cache-writing and no-cache checks) must run through the same short-lived guardian as the periodic worker. The guardian owns the process-group deadline and cleanup, including a CLI descendant retaining the API flock; a timeout must never kill only the Node leader and leave that descendant running. The synchronous caller waits for the guardian to finish cleanup before accepting output or reporting failure. The inner process-group deadline is 60 seconds; the synchronous outer backstop is 62 seconds with SIGTERM, leaving two seconds for cleanup rather than killing the guardian with SIGKILL. Guardian session isolation also lets it clean up after a terminal SIGHUP terminates the caller. Regression acceptance invokes both actual public helper paths with a synthetic child/grandchild, then verifies descendant exit and lease reacquisition after timeout.

The five-second foreground lease budget and each helper's remaining timeout must use one monotonic clock. Wall time remains for durable due/cooldown timestamps, but clock adjustments cannot increase an in-process wait budget. A synthetic test moves the injected wall clock backward by ten seconds while monotonic elapsed time advances; total helper work plus sleeps must still fit five seconds. No machine-clock change is needed or permitted for the test.
